## 2026-07-28 - Active Session Expiration Bypass
**Vulnerability:** The admin panel toolkit restored and checked session expiration only on boot/load. Once an operator was logged in, if they left the tab/page open indefinitely, the session was never actively checked for expiration, allowing continued access to the user interface even after the token's expiration time had elapsed.
**Learning:** Checking session expiration solely at bootstrap/initialization creates an active session state bypass. While API requests might eventually fail due to an expired token, the client-side UI remains accessible and exposes cached/rendered administrative data, which violates the principle of immediate session revocation.
**Prevention:** Implement a reactive effect/observer that actively monitors the active session's `expires_at` property. Calculate the remaining lifetime of the session and establish a timeout/timer to trigger logout automatically as soon as the session expires. Clean up any active timers on component unmount or session changes.
